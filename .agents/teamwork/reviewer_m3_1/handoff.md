## 6. Adversarial Challenge Report

### Challenge Summary
**Overall Risk Assessment**: LOW

### Challenges

#### Challenge 1: BF2Editor vs Runtime Argument Propagation in `init.con`
- **Assumption Challenged**: That passing arguments `BF2Editor` and `v_arg2` to child scripts is safe across both editor and game client runtime.
- **Attack Scenario**: If a child script does not handle arguments or expects a specific parameter order, it could fail to execute or produce console errors.
- **Blast Radius**: Level fails to load in either BF2Editor or in-game dedicated server.
- **Mitigation & Verification**: In `StaticObjects.con`, line 2 conditionally inspects `if v_arg1 == BF2Editor` to set `console.allowMultipleFileLoad 0`. Passing `BF2Editor` enables this block. In runtime, `StaticObjects.con` is invoked with no arguments. For other scripts (`Terrain.con`, `Sky.con`), Refractor 2 console parser ignores superfluous trailing arguments on `run <script>` commands if the target script does not reference `v_arg*`. Both modes execute safely.

#### Challenge 2: Filesystem Inode Hardlink Mutation
- **Assumption Challenged**: Hardlinking `Heightmap.raw` and `ColorMap.dds` into `levels/slovenia_golovec/` saves space without risking in-place modification of root raw data.
- **Attack Scenario**: If an editor or tool opened `levels/slovenia_golovec/Heightmap.raw` in read-write mode and altered bytes, the root `Heightmap.raw` would be modified in-place.
- **Blast Radius**: Source data corruption across the workspace.
- **Mitigation & Verification**: Both `Heightmap.raw` and `ColorMap.dds` permissions are `-rw-rw-r--` owned by `ator`, and are treated as immutable terrain textures by the runtime. If unlinking is desired, `safe_hardlink_or_copy()` in `assemble_level_package.py` safely unlinks before creating new links.
