
AASv4 Game Mode
===============

This tutorial provides instructions for setting up control points on a map using AASv4 (Advance and Secure version 4).

Tools Needed
------------

* :program:`BF2 Editor`

Prerequisites
-------------

* A map with at least one gameplay layer already created (e.g., AAS 64).

.. note::

   This tutorial does not cover creating combat zones, object spawners, or spawn points, as these processes remain unchanged from previous AAS versions.

.. seealso:: For fundamental information on layers

   * `[Map Tutorial] Layers (16, 32 And 64 Size Maps etc) <https://www.realitymod.com/forum/f189-modding-tutorials/13937-map-tutorial-layers-16-32-64-size-maps-etc.html>`_
   * `Creating a Basic Level - BFEditor <http://www.bfeditor.org/wiki/index.php?title=Creating_a_Basic_Level>`_

Setting Up Teams
----------------

The control point (CP) capture sequence begins with ``Team 1``. The CP closest to ``Team 1``'s main base is designated CP#1, and the sequence progresses outwards from there.

To designate teams, edit the :file:`init.con` file located in the map's main folder. Open this file to find the ``LevelSettings`` section:

.. code-block:: text

   rem *** Generated by BF2Editor ***
   if v_arg1 == BF2Editor

   run Heightdata.con
   LevelSettings.InitWorld
   run Terrain.con BF2Editor
   run StaticObjects.con BF2Editor
   run Sounds.con
   run Sky.con BF2Editor
   run Editor/GamePlayObjects.con host
   UndergrowthEditable.create
   Undergrowth.load Levels\yourmapname\
   run Overgrowth/Overgrowth.con
   Overgrowth.editorEnable 1
   run AmbientObjects.con BF2Editor
   run Water.con
   run TriggerableTemplates.con BF2Editor

   else

   run Heightdata.con
   run Terrain.con v_arg2
   run Sky.con v_arg2
   run CompiledRoads.con
   run Sounds.con
   run tmp.con v_arg1
   Undergrowth.load Levels\yourmapname\
   run Overgrowth/Overgrowth.con
   run Overgrowth/OvergrowthCollision.con
   run AmbientObjects.con
   run Water.con
   run TriggerableTemplates.con
   run Fields.con

   endIf

   rem ------------------------------- LevelSettings -------------------------------
   rem -----------------------------------------------------------------------------

   run ../../Factions/faction_init.con 1 "gb"
   run ../../Factions/faction_init.con 2 "ch"

   rem -----------------------------------------------------------------------------

   gameLogic.setBeforeSpawnCamera -728/24/-1075 -124.292/-2.23791/0

   if v_arg1 == BF2Editor
   LevelSettings.CustomTextureSuffix "Woodland"
   else
   texturemanager.customTextureSuffix "Woodland"
   endIf
   rem -----------------------------------------------------------------------------

   GameLogic.MaximumLevelViewDistance 800

   rem -----------------------------------------------------------------------------

   gameLogic.setDefaultNumberOfTicketsEx 16 1 50
   gameLogic.setDefaultNumberOfTicketsEx 16 2 50
   gameLogic.setDefaultNumberOfTicketsEx 32 1 250
   gameLogic.setDefaultNumberOfTicketsEx 32 2 250
   gameLogic.setDefaultNumberOfTicketsEx 64 1 300
   gameLogic.setDefaultNumberOfTicketsEx 64 2 300
   gameLogic.setDefaultNumberOfTicketsEx 128 1 50
   gameLogic.setDefaultNumberOfTicketsEx 128 2 50
   gameLogic.setDefaultTimeToNextAIWave 8
   gameLogic.setTicketLossAtEndPerMin 1000
   gameLogic.setTicketLossPerMin 1 20
   gameLogic.setTicketLossPerMin 2 20

Locate the section beginning with ``rem ------------------------------- LevelSettings -------------------------------`` to define the teams. Consult the :file:`init.con` files of other maps to identify the desired team abbreviations. Assign ``Team 1`` to the first line and ``Team 2`` to the second line, then save the file.

Placing Control Points (CPs)
----------------------------

To create control points (CPs) in the BF2 Editor:

#. Open the BF2 Editor in :guilabel:`Level` mode.
#. In the right-hand column of the :guilabel:`Editor` screen, select the desired layer.
#. Navigate to the preferred location for the control point.
#. :kbd:`Right-Click` the location and select :guilabel:`Create ControlPoint` from the menu.
#. Enter a name in the prompt.

Project Reality uses a specific naming convention. Use the following template rather than the default editor name:

.. code-block:: text

   cpname_nameofthemap_gamemode_nameofcpalloneword

   Example: "cpname_kashan_desert_aas64_northvillage"

   "cpname" = always the literal text "cpname"

   "nameofthemap" = the name of your map; use underscores (_) if spaces are needed.

   "gamemode" = the game mode and its corresponding number. Valid values include:
   aas
   skirmish
   insurgency
   training
   followed immediately by 16, 32, or 64 (no space).

   "nameofcpalloneword" = the name of the control point, written as a single word.
   Only alphabetic characters should be used.

   All characters must be in lowercase. Repeat this process for each control point you wish to create.

SupplyGroupId
-------------

The sequence and selection of CPs are determined by the :guilabel:`SupplyGroupId` (SGID) found in the control point's tweaker bar.

.. image:: http://i.imgur.com/ZbOThdS.jpg
   :align: center

In AASv4, change the default :guilabel:`SGID` value from :guilabel:`-1` to a specific number based on the desired configuration.

Main Bases
----------

In Project Reality, main bases serve as safe zones for spawning, vehicle repairs, and support functions. When configuring AAS, determine the operation of the main bases. A common approach is to make them uncappable and assign them to the corresponding team.

To configure a main base using the tweaker bar:

* :guilabel:`Team`: :guilabel:`1` (or :guilabel:`2`)
* :guilabel:`unabletochangeteam`: Enabled
* :guilabel:`Team 1`: :guilabel:`1`
* :guilabel:`Team 2`: :guilabel:`1`

If a main base must be cappable, assign it a unique :guilabel:`SGID`.

To remove the :guilabel:`SGID` for ``Team 2``'s main base, open the text file and delete the line ``ObjectTemplate.supplyGroupId -1``.

Basic Randomization
-------------------

This method is suitable for smaller maps (1km and 2km) with a limited number of control points.

Control Points (CPs) are assigned a two-digit :guilabel:`SGID` in the format AB, where:

:A: Represents the CP's order in the sequence, starting from the CP closest to ``Team 1``'s main base.
:B: Indicates how many CPs should be active if multiple CPs share the same 'A' number.

To ensure a control point is always active and not randomized, assign it a unique 'A' digit and set 'B' to :guilabel:`0`.

.. admonition:: Example

   .. image:: http://i.imgur.com/jYI34Pg.jpg

In this example, Team 1 is on the carrier, and Team 2's main base is the hashed area. The CP layout is:

* :guilabel:`CP#1`: Village
* :guilabel:`CP#2`: Either Bridge or Farm will be active. Both share an 'A' digit of 3, and the 'B' digit of 1 tells the system to randomly select only one.
* :guilabel:`CP#3`: Junction

Team 1 must capture Village, then either Farm or Bridge, and finally Junction. Team 2 must attack Junction, then either Farm or Bridge, and finally Village.

To make both Farm and Bridge active, change the "B" digit from 1 to 2. The system will then select both CPs as CP#2, requiring a team to hold both before proceeding to the next objective.

.. image:: http://i.imgur.com/qgwLQ6j.jpg
   :align: center

AASv4 Attack Routes
-------------------

Attack routes are implemented by adding a third digit to the ``SupplyGroupId``, using the "ABC" format, where:

:A: Order in the sequence.
:B: Number of active CPs sharing the same 'A' digit.
:C: Route designation.

The third digit instructs the game to select a specific route.

.. image:: http://i.imgur.com/zequiL9.jpg
   :align: center

The example shows two routes: Blue and Green. The :guilabel:`SGID` values include a third digit, with Green assigned as route #1 and Blue as route #2. The game randomly selects one of these routes upon map load.

Up to 9 routes can be implemented.

Adding complexity to routes can be achieved by adding random flags, similar to the process described in the earlier section of this tutorial.

.. image:: http://i.imgur.com/gW1DX0X.jpg
   :align: center

In the example above, a new CP named Village is added to the Blue route. It shares the same :guilabel:`SGID` as Port. Breakdown of its ABC components:

:A = 2: Second CP in the sequence.
:B = 1: Since both Village and Port begin with ``A = 2``, setting ``B = 1`` instructs the map to select only one.
:C = 2: Route designation.

If the game selects route #2, it will choose either Port or Village.

Same Area, Different CPs
------------------------

AASv4 allows multiple control points (CPs) for the same geographical area by assigning them to different routes.

For example, to have a CP area be part of more than one route, create an additional CP with a slightly different name:

.. image:: http://i.imgur.com/gri1avK.jpg
   :align: center

To avoid confusion, include the route number in the CP name:

* :guilabel:`Green Route "Village"`: ``cpname_mapname_aas64_1village``
* :guilabel:`Blue Route "Village"`: ``cpname_mapname_aas64_2village``

The Editor can then be used to adjust these CPs so they have either the same radius or slightly different ones.

Variety can also be introduced by using multiple CPs for an area.

.. image:: http://i.imgur.com/geQRsm1.jpg
   :align: center

By using multiple CPs, a single area can be configured to present different options depending on the selected route. For example, if route #3 (Orange) is selected, players might encounter a 150m North City, a 150m South City, or a 300m Entire City flag. Because ``B = 1``, the game selects only one, and because ``C = 3``, it does not interfere with CPs in other routes.

Combining these elements:

.. image:: http://i.imgur.com/GObRqjU.jpg
   :align: center

Appropriate CP naming, including the route number, ensures clarity and facilitates complex design.

Using One CP on All Routes
--------------------------

A single control point (CP) can be included in all routes. Consider this AASv4 setup for Fools Road:

.. image:: http://i.imgur.com/Tn9St1O.jpg
   :align: center

CP#1 and CP#5 are part of every route. This is useful for critical final objectives, such as a missile silo or an airfield, that both teams must capture or defend. In such cases, assign the CP a single digit :guilabel:`SGID`. If the CP is at the start of a route, its :guilabel:`SGID` would be ``1``. Set both main bases to ``SGID = -1``, as they are not part of any route.

If a shared CP is at the **end** of a route, assign it a single-digit :guilabel:`SGID` that marks the end of all routes. For example, in the Fools Road map, all routes end at flag #5.

.. important::

   There must be no gaps in the sequence. A route with :guilabel:`SGID`s of ``1``, ``205``, ``305``, and ``5`` would fail, as the gap between ``305`` and ``5`` prevents the system from working correctly.

Main Base Considerations
------------------------

* **Spawners and Main Bases**: If a main base is part of a route, it must have a single-digit :guilabel:`SGID`` (e.g., ``Team 1 = 1`` and ``Team 2 = [last number in routes]``). This is because all **spawn points** and **objectspawners** are linked to this CP. Assigning spawners to a route that is not selected can cause issues. The best practice is to link spawners to an uncappable CP that is not assigned to any specific route (e.g., ``Team 1 = 1`` and ``Team 2 = -1``).
* **CP Marking**: Except for CnC mode, most main bases (99%) should be marked with a Control Point (CP) to help players identify them and avoid "domes of death" (areas where players are instantly killed if they enter). Even if the main base is uncappable and not part of any route, its CP must be marked on the map.

In the Fools Road example, spawners can be linked to the nearest flag (making it cappable) or to a dedicated, uncappable CP.

Flag Names on Minimap
---------------------

When the map is nearing completion or is ready for playtesting, perform these steps:

#. Add flag names to the localization file.

   To prevent players from seeing internal names (e.g., ``cpname_map_aas64_flagname``), follow this tutorial: `Map Localisation Tutorial <https://www.realitymod.com/forum/f189-modding-tutorials/63107-map-tutorial-map-localisation.html>`_

#. Ensure flag names do not extend beyond the minimap boundaries.

   Verify that flag names are displayed correctly on the minimap and do not run off the edges. This issue frequently occurs with perimeter flags. To fix this, return to the editor and adjust the "MinimapNameOffset" values:

   .. image:: http://i.imgur.com/fv292tj.jpg

   Expanding the options allows modification of the X (horizontal) and Y (vertical) values. Adjusting these values typically requires trial and error within the game.
